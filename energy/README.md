# 🔋 Energy Optimizer

하루의 **시간**을 **에너지(HP·MP)** 로 환산해서, 한정된 자원을 어디에 쓸지 정하는 앱.
"오늘 내가 몇 점인가"가 아니라 **"이걸 감당할 수 있나 / 지금 뭘 하는 게 맞나"** 에 답하는 것이 목표다.

- **HP** — 몸의 자원 (근육 피로·심폐 부담·신체적 피곤)
- **MP** — 머리의 자원 (집중력·인지/의사결정/사회적 피로)
- **예산(Budget)** — 지금부터 취침까지, 안전 예비분을 남기고 쓸 수 있는 양

## 핵심 루프

```
활동 선택 → 예상 부하 → 실제 수행 → 2문항 피드백 → 개인계수 학습 → 다음 예측이 정확해짐
```

사용자는 활동이 끝나고 **"앱 예상보다 어땠는지"** 만 답한다(😌 😐 😓 🥵).
예측에는 이미 개인계수가 반영돼 있으므로, 그 비율을 EMA로 곱해 나가면 계수가 자연히 수렴한다.
20번쯤 쌓이면 "당신에게 테니스는 기본보다 몸 부하가 약 40% 높습니다" 같은 문장이 나온다.

## 모델 — Real Life RPG 엔진 이식

HP/MP는 "깎아온 누적값"이 아니라 **매번 다시 계산되는 파생값**이다. 계산기는
[Real Life RPG](../../Documents/Real%20Life%20RPG)의 `realtime/engine/`을 그대로 옮긴
[`src/engine/rlr.js`](app/src/engine/rlr.js)다.

```
아침 시작값 = 잠으로 채운 양 (수면 시간 × 질) − 14박 수면부채
HP = 시작값 − 깨어있는시간×0.15 − 운동 즉시피로 − 지연 근피로(DOMS) − 걷기 + 휴식 + 영양 − 컨디션
MP = 시작값 − 수면압×0.50 + 일주기 리듬 − 인지·사회 부하 + 휴식·낮잠 − 운동 여파 − 스트레스
```

- **2-process 모델(Borbély)**: 수면압 `1−e^(−t/18.2h)` + 기상 기준 일주기 곡선
- **운동 부하**: MET × 강도 → 포화 곡선 → 즉시 피로(τ=3h 감쇠) / 지연 근피로(24h 정점, DOMS)
- **수면부채**: 최근 14박을 0.82^n 가중, 최대 −15%
- **낮잠**: 잔 시간의 1.5배만큼 수면압을 지운다

원본은 웨어러블(심박·HRV)을 읽지만 이 앱은 손기록이므로 같은 자리에 수동 입력을 넣었다 —
심박 예비율 → **강도 1~10**, HRV → **수면의 질 4단계**, MET 카탈로그 → 활동의 **신체 부하 phys**.
원본에 없던 **영양**(식사·수분)은 이 사용자 기록에서 공복·혈당이 반복 변수라 추가했다.
상수·곡선·가중치는 원본 값 그대로다.

`오늘 → 왜 이 값인가`를 열면 항목별 기여도가 그대로 보인다.

## 파라미터 최적화

활동 기록이 6회 이상 쌓이면 [`fit.js`](app/src/engine/fit.js)가 활동마다

```
시간당 비용 = a + b × (강도 − 5)
```

를 최소자승으로 직접 추정해 모델값을 대체한다(`a` 보통 강도 비용, `b` 강도 민감도).
표본이 적을 땐 모델값 쪽으로 끌어당기고(n/(n+6)), 강도를 거의 바꾸지 않은 기록만 있으면
기울기는 추정하지 않는다. 활동 탭에서 모델값 · 측정값 · 반영 비중 · R²를 볼 수 있다.

## 하루 블록

오늘 화면 아래쪽이 기상~취침을 **30분 칸**으로 자른 격자다. 빈 칸을 누르면 그 시각으로 기록이 열리고,
찬 칸을 누르면 그 기록을 고친다. 계획은 옅게, 지금 시각은 테두리로 표시된다.
`채움 %`는 하루 중 실제로 기록된 비율 — 빈 칸이 많은 날이 어디로 샜는지 보여 준다.

## 건강 데이터

| 항목 | 넣는 곳 | 엔진에서 쓰이는 곳 |
|---|---|---|
| 수면 | 체크인의 취침·기상 시각 | 아침 시작값(수면 계수) + 14박 수면부채 |
| 걸음 | 체크인에 직접 입력하거나 삼성 헬스 가져오기 | 걷기 HP 소모 (1,000걸음 ≈ 0.4). 워치 값이 있으면 활동에서 추정한 걷기를 대체 |
| 운동 | 활동 기록 또는 삼성 헬스 운동 세션 | MET × 강도 → 즉시 피로 + 지연 근피로 |
| 영양 | 체크인의 3단계 또는 **사진 판별** | HP/MP 보정 (±4% / ±3%) |

### 삼성 헬스

삼성 헬스는 웹에서 바로 읽을 통로가 없다(워치 데이터는 Health Connect → 안드로이드 앱만 접근 가능).
대신 **삼성 헬스 앱 → 설정 → 개인 데이터 다운로드**로 받은 CSV를 설정에서 그대로 읽는다
([`samsung.js`](app/src/engine/samsung.js)).

- `com.samsung.shealth.sleep.*` → 날짜별 취침·기상·수면시간
- `com.samsung.shealth.tracker.pedometer_day_summary.*` → 날짜별 걸음
- `com.samsung.shealth.exercise.*` → 운동 세션 (평균 심박에서 강도 1~10을 역산)

버전마다 열 이름 접두사가 달라서 이름 끝부분으로 느슨하게 찾는다. 운동 종목 코드는 확실한 것만
매핑하고 나머지는 일반 운동으로 떨어뜨리므로, 가져온 뒤 블록에서 눌러 활동을 고쳐 주면 된다.

### 음식 사진 판별

서버가 없으므로 **사용자 본인의 Anthropic API 키로 브라우저에서 직접** 호출한다
([`food.js`](app/src/engine/food.js)). 키는 이 기기의 localStorage 에만 있다.
사진은 보내기 전에 긴 변 1024px JPEG 로 줄이고, 모델은 설정에서 고른다(기본 `claude-opus-5`).
응답은 JSON 하나로 받아 음식·열량·단백질·영양 등급(0~2)·한 줄 코멘트로 저장한다.

## 캘린더 · 알림

서버가 없어 실시간 양방향 동기화는 불가능하다. 대신 iCalendar 표준으로 주고받는다.

- **가져오기** — 계획 탭 `📥 캘린더` → .ics 파일 선택 → 제목으로 활동·강도를 추정 → 골라서 계획에 추가.
  라이브러리 이름과 정확히 맞지 않아도 낱말 사전으로 종류를 잡는다("민수랑 저녁" → 친구 만나기, "스탠드업 미팅" → 미팅)
- **자동 가져오기** — 설정에서 켜면 앱을 열 때(30분에 한 번) 구독 주소를 읽어 추정된 일정을 계획에 담는다
- **한 건씩 구글 캘린더로** — 계획 목록의 📅 를 누르면 구글 캘린더 일정 만들기 화면이 그 내용으로 열린다
- **내보내기** — 계획 탭 `📤 캘린더로 내보내기` → 일정 + `VALARM`(N분 전 알림)이 들어간 .ics.
  캘린더 앱에서 열면 기기 알림으로 뜨므로 **이쪽이 가장 확실하다**
- **앱 알림** — 설정에서 권한을 켜면 앱이 살아 있는 동안 N분 전에 알림. 웹푸시가 없어 앱을 완전히 닫으면 못 온다
- **구독 주소** — 구글 캘린더의 비공개 ICS 주소를 넣어 시도할 수 있지만, CORS 때문에 실패하는 경우가 많다
