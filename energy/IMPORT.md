# 기존 데이터 가져오기

다른 대화/앱에서 쌓인 Energy Optimizer 데이터를 이 앱으로 옮길 때 필요한 것들.

경로: **설정 → 가져오기 → JSON 파일 선택**
(가져오면 현재 데이터를 **대체**합니다. 먼저 `내보내기(JSON)`로 백업하세요.)

---

## 1. 무엇을 건져와야 하나

우선순위 순. **B만 있어도 앱은 제대로 굴러갑니다** — 개인계수·통계·인사이트는 B에서 자동 재계산됩니다.

| | 항목 | 필요한 필드 | 없으면 |
|---|---|---|---|
| **A** | **활동 정의** | 이름, 이모지, 분류, 시간당 HP/MP, 대표 시간(분), 회복 비용, 성과 기록 여부 | 기본 35종에서 이름으로 매칭. 못 찾으면 기록에서 역산해 자동 생성 |
| **B** | **활동 기록** ⭐ | 날짜·시각, 활동, 분, 강도, **실제 HP 소모**, **실제 MP 소모**, (성과, 메모) | 학습·인사이트가 전부 비어 있음 |
| **C** | 개인 계수 | 활동별 kHp, kMp, 횟수 | B가 있으면 자동 재계산 (오히려 이쪽이 정확) |
| **D** | 프로필 | 목표 수면, 안전 예비분, 기상/취침 시각 | 기본값(7.5h / 20 / 7시 / 23시) |
| **E** | 일자별 상태 | 날짜별 수면 시간·질, 컨디션 태그, 현재 HP/MP | 오늘 아침 체크인부터 새로 시작 |
| **F** | 계획 | 시각, 활동, 분, 강도 | 빈 계획으로 시작 |

### 반드시 확인할 것 — 숫자의 의미

- `hp` / `mp` 는 **그 활동으로 쓴 양(소모량, 양수)** 입니다. **남은 HP가 아닙니다.**
  (테니스 90분에 HP가 75→45로 떨어졌으면 `hp: 30`)
- 회복형 활동(낮잠·산책·명상)은 **음수**로 적습니다. (`hp: -12`)
- 0~100 스케일 기준입니다. 다른 스케일(0~10 등)을 썼다면 변환 배수를 알려주세요.

## 2. 형식

### 최소 형식 — 이것만 있으면 됩니다

```json
{
  "logs": [
    { "활동": "테니스",     "날짜": "2026-09-01 18:00", "분": 90,  "강도": 7, "hp": 30, "mp": 12 },
    { "활동": "코딩(일반)", "날짜": "2026-09-02 21:00", "분": 120, "강도": 5, "hp": 4,  "mp": 22, "성과": 4 },
    { "활동": "낮잠",       "날짜": "2026-09-02 14:00", "분": 30,             "hp": -12, "mp": -16 }
  ]
}
```

키는 한글/영문 별칭을 모두 받습니다:

| 뜻 | 받는 키 | 필수 | 기본값 |
|---|---|---|---|
| 활동 | `활동` `activity` `act` `actId` `name` | ✅ | — |
| 시각 | `날짜` `일시` `date` `start` `startTs` `when` | ✅ | 시각 없으면 정오, 없으면 **건너뜀** |
| 길이(분) | `분` `minutes` `min` `duration` `durationMin` | ✅ | 없으면 **건너뜀** |
| 강도 | `강도` `intensity` (1~10) | | 5 |
| HP 소모 | `hp` `HP` `actualHp` | | 0 |
| MP 소모 | `mp` `MP` `actualMp` | | 0 |
| 성과 | `성과` `output` (1~5) | | 없음 |
| 메모 | `메모` `note` | | 없음 |

시각은 `1788253200000`(ms) · `"2026-09-01T18:00"` · `"2026-09-01 18:00"` · `"2026/09/01"` 다 됩니다.

### 활동 정의까지 함께 옮길 때

```json
{
  "custom": [
    { "id": "c_pilates", "name": "필라테스", "emoji": "🤸", "cat": "exercise",
      "hp": 8, "mp": 3, "dur": 50, "rec": 0.3,
      "phys": 7, "ment": 3, "soc": 1, "emo": 1, "out": false, "builtin": false }
  ],
  "logs": [ ... ]
}
```

- `cat`: `exercise` | `work` | `social` | `life` | `recover`
- `hp` / `mp`: **시간당** 소모량 (강도 5 기준). 회복형은 음수
- `rec`: 회복 비용 0.15(낮음) / 0.45(중간) / 0.8(높음)
- `out`: 끝나고 성과를 묻는 활동인지
- `phys/ment/soc/emo`: 0~10, 부하 성격(표시·추천용)

### 전체 형식

앱의 `내보내기(JSON)` 결과와 같은 모양입니다. 있는 키만 넣으면 나머지는 기본값이 채워집니다.

```json
{
  "v": 1,
  "profile": { "sleepTarget": 7.5, "floor": 20, "wakeHour": 7, "bedHour": 23 },
  "state":   { "hp": 72, "mp": 64, "debt": 0, "ts": 1788253200000 },
  "custom":  [ /* 위 활동 정의 */ ],
  "overrides": { "tennis": { /* 기본 활동 수정본 */ } },
  "hidden":  ["networking"],
  "learn":   { "tennis": { "kHp": 1.4, "kMp": 1.2, "n": 12 } },
  "logs":    [ /* 위 기록 */ ],
  "plan":    [ { "활동": "테니스", "시각": "2026-09-07 18:00", "분": 90, "intensity": 6 } ],
  "days":    { "2026-09-01": { "sleepHours": 6.5, "quality": 0.7, "flags": ["stress"], "checkedIn": true } }
}
```

- `flags`: `sick` `stress` `busy` `cycle` `peak`
- `quality`: 0.5 뒤척임 / 0.7 보통 / 0.85 좋음 / 1.0 푹 잠

## 3. 가져올 때 앱이 하는 일

1. 활동 이름을 기본 라이브러리 35종과 대조 → 같으면 그 활동으로 연결
2. 못 찾은 이름은 **새 활동으로 생성** (시간당 비용은 그 기록에서 역산)
3. `pred`(예상 부하)가 없으면 엔진으로 다시 계산
4. `ratio = 실제 ÷ 예상` 을 시간순으로 훑으며 **개인계수(kHp/kMp)를 처음부터 다시 학습**
5. 결과 배너로 보고: `기록 n건 · 계획 n건 · 새 활동 n개 · 건너뜀 n건`

즉 **예상값이나 계수를 억지로 맞춰 올 필요가 없습니다.** 실제 소모량과 시간만 정확하면 됩니다.

## 4. 이전 대화에 그대로 붙여넣을 요청문

```text
지금까지 이 대화에서 만든 Energy Optimizer 데이터를 JSON 파일 하나로 정리해줘.
설명 없이 코드블록 하나에 JSON만. 형식은 아래를 정확히 지켜줘.

{
  "profile": { "sleepTarget": 목표수면시간, "floor": 안전예비분, "wakeHour": 기상시, "bedHour": 취침시 },
  "state":   { "hp": 현재HP, "mp": 현재MP, "debt": 0 },
  "custom":  [ { "name": "활동이름", "emoji": "🎾", "cat": "exercise|work|social|life|recover",
                 "hp": 시간당HP소모, "mp": 시간당MP소모, "dur": 대표시간분,
                 "rec": 0.15|0.45|0.8, "out": true|false, "builtin": false } ],
  "logs":    [ { "활동": "활동이름", "날짜": "2026-09-01 18:00", "분": 90, "강도": 7,
                 "hp": 실제HP소모, "mp": 실제MP소모, "성과": 1~5, "메모": "" } ],
  "days":    { "2026-09-01": { "sleepHours": 6.5, "quality": 0.7, "flags": [] } }
}

규칙:
- hp/mp는 "그 활동으로 쓴 양"(양수), 0~100 스케일. 남은 HP가 아니라 소모량.
- 회복되는 활동(낮잠·산책·명상)은 음수로.
- 강도는 1~10, 보통이 5. 모르면 생략.
- 날짜·활동·분은 반드시 있어야 하고, 나머지는 모르면 빼도 됨.
- 없는 값은 추측해서 지어내지 말고 그냥 빼줘.
- 기록이 많으면 잘라내지 말고 전부.
```

## 5. 이전 대화 원문 (2026-05-01 ~ 09-02) — 반영 완료

원문 로그 → `energy/data/legacy-import.json`.
변환기: [`tools/convert_backup.py`](tools/convert_backup.py) (표를 고치고 다시 실행하면 재생성)

원문에 **활동별 분 단위 시간과 HP/MP 소모량이 없어 기록(logs)은 만들지 않았다.**
없는 숫자를 지어내면 개인계수가 처음부터 틀린 값으로 학습되기 때문이다. 확인된 것만 옮겼다:

| | 내용 |
|---|---|
| 활동 44개 | 사용자의 실제 어휘. 테니스는 형태별로 9종(레슨/개인연습/팀훈련/경기/대회/볼머신/서브연습/랠리/피딩)으로 나눴다 — 원문에서 부하가 형태별로 뚜렷하게 다르기 때문 |
| 일자 87일 | 05-01 ~ 09-02. **취침·기상 시각(79일)**, 수면 시간, 추가 수면, 낮잠, 아침 HP/MP(59일), 컨디션 플래그, Must/Nice, 실제 수행, 관찰 메모 |
| 상태 | 마지막 관측(09-02) HP 60 · MP 60 → 지금 값은 **체크인으로 보정** 필요 |
| 프로필 | 안전 예비분 25, 목표 수면 7.5h, 기상 8시 / 취침 24시 |

취침 시각을 별도 필드(`bed`/`wake`)로 보존한 것이 핵심이다. 이 사람의 데이터에서는
**취침 시각이 수면량을 결정하고, 수면량이 다음 날 상한을 정한다**는 사슬이 그대로 보인다.

`energy/data/`는 `.gitignore`에 걸려 있어 커밋되지 않는다(개인 기록이라 의도된 동작).

## 6. 스키마가 많이 다르면

그쪽 데이터가 위 모양과 크게 다르면(예: 0~10 스케일, 카테고리별 점수 배열, CSV 등)
샘플 몇 줄만 보여주면 변환기를 붙이겠습니다. 변환 로직은
[`app/src/engine/importer.js`](app/src/engine/importer.js) 한 파일에 모여 있습니다.
